# Хомыч · фронтенд бота

Актуальная редакция: 12 ноября 2026. React + TypeScript. Визуальная основа — [дизайн-код команды Origination в Figma](https://www.figma.com/design/pDmYotOu0D7yKMmhoN9UtG/Avito?node-id=10-1289): Onest, палитра, прямые углы и чёрные линии 2 px. Продуктовая основа — требования 0.4, BPMN P00–P17 v3 и явное уточнение концепции от 12 ноября.

## Концепция

Продукт — бот, который **сам пишет по срокам в одну переписку**. Наступила дата → короткое сообщение с чек-листом стажёру → соответствующие пункты помощи бадди и руководителю. Стажёр также задаёт вопросы AI. Подсказки вопросов остаются над полем ввода.

В чате нет боковой шкалы, меню этапов и отдельной панели «Ближайшая точка». Следующая точка может быть короткой строкой в конце сообщения. Предыдущие сообщения остаются в общей истории. Отметки не влияют на время следующего сообщения.

Бадди и руководитель получают **чек-лист**, а не только общий абзац: что им нужно сделать совместно со стажёром или в помощь ему. Пункт связан с исходным пунктом стажёра. «Получи доступы» → бадди «Вместе определите нужные доступы и пройдите подачу заявки»; руководителю «Если нужно согласование, помоги получить доступы для задачи».

## Посмотреть

Локальное превью: **http://127.0.0.1:4173/**. Это адрес компьютера, где запущен проект. Для передачи используется папка frontend в приватном репозитории; прежний ZIP сохранён как история. [Полная спецификация команды](../output/ai-buddy-team-specification.docx) и [подключение сервера](../docs/ai-buddy/server-handoff.md).

- **Стажёр → Сообщения:** входящие чекпоинты, отметки, ссылки, AI-диалог, саджесты, основания ответа.
- **Бадди / Руководитель → Сообщения:** соответствующий чек-лист совместных действий. Личного диалога стажёра и AI-композера здесь нет.
- **Руководитель → Сценарий:** список вариантов по стажёрам с поиском, фильтрами и статусами. «Создать сценарий» открывает конфигуратор 6/9 месяцев. Нажатие на запись продолжает её черновик; «К списку сценариев» возвращает назад. Автосохранение и ручное подтверждение показывают результат записи. Другой опубликованный вариант заменяет действующий после подтверждения.
- **Материалы:** вариант управления знаниями — чтение, добавление TXT/Markdown/текста, обновление и исключение. Владелец ещё не согласован.
- **HR:** явно помеченный вариант организационных сведений и материалов.

Верхняя серая полоска — инструменты проверки макета. В ней можно сменить роль, включить ширину 414 px и открыть «Состояния». Там находится **демонстрационная дата**: укажите дату, нажмите «Применить дату» и закройте окно. Бот сам добавит наступившие сообщения. Повтор той же даты не создаёт дубль. Эти настройки не являются пользовательским интерфейсом бота.

## Реализация и границы

Работает одна хронологическая лента: новые чекпоинты и диалог добавляются в неё. Локальная проверка даты выполняется при открытом приложении каждые 15 секунд, при смене контрольной даты и публикации. Отметки не проверяются. Доставленное сообщение сохраняется со своей версией сценария; будущая публикация не переписывает историю.

Коллекция сценариев, отдельные черновики, переписка и отметки каждого стажёра и демоматериалы сохраняются в localStorage (`homych.frontend.bot.v3`). Прежняя запись v2 переносится без удаления оригинала. Изменения синхронизируются между открытыми вкладками; перед редактированием читается свежая версия. При ошибке записи данные остаются в открытой вкладке и доступна повторная попытка. Формы, предпросмотр, валидация, источники, темы, мобильные окна и ошибки интерактивны.

Это фронтенд-прототип. Настоящего Go API, PostgreSQL, Qwen/DeepSeek, embeddings/RAG и корпоративных интеграций пока нет. Ответы выбирает локальная функция, которая не передаёт данные модели. Доставка при закрытом приложении требует серверного планировщика и выбранного канала; локальный таймер этого не обеспечивает.

Имена, даты, инструкции и задачи синтетические. Реальные внутренние ссылки не предоставлены: до подключения кнопки открывают обозначенную памятку/состояние неподключённого инструмента. Заданный в конструкторе http/https открывается в новой вкладке. Результаты, встречи и решения остаются вне бота. Прямая заявка выключена по умолчанию и помечена OQ08; её состояние — демонстрация в памяти приложения.

Переключатель роли служит для просмотра макета, не является авторизацией. Изоляцию реальных данных должен обеспечить сервер. HR, оператор знаний и детали интеграций сохраняют статусы предложений/открытых вопросов. Макет не превращает их в согласованные функции MVP.

## Работа с сервером (VITE_API=on)

Без переменной `VITE_API` прототип работает как раньше: все данные в localStorage этого браузера. С `VITE_API=on` он ходит в Go-бэкенд (`../backend`).

**Всё в Docker:** из корня репозитория `docker compose up --build`, затем открыть http://localhost:8088. Nginx отдаёт собранный фронт и пересылает `/api` в бэкенд, поэтому страница и API живут на одном адресе.

**Разработка с горячей перезагрузкой:** `docker compose up db api` в корне, затем здесь `cp .env.example .env.local` и `npm run dev -- --host 127.0.0.1 --port 4173`. Vite пересылает `/api` на http://localhost:8080 (адрес меняется через `VITE_API_TARGET`).

Что уже идёт через сервер:

- **Вход.** Экран выбора тестового пользователя (`src/Login.tsx`), сессия в HttpOnly-cookie, роль определяется сервером. Вместо переключателя ролей вверху — «Вход: … · Выйти».
- **Сценарии руководителя.** Список, создание, автосохранение черновика (через 0,7 с после правки, с `If-Match`), публикация с заменой активного варианта. Если черновик изменили в другой вкладке, появляется сообщение и кнопка «Загрузить актуальную версию».

**Демо-данные.** При первом запуске сервер создаёт сценарии для Саши (опубликован), Маши (черновик) и Кирилла из команды Ирины — см. [backend/README.md](../backend/README.md#демо-сценарии). Руководитель после входа сразу видит стажёра с активным планом. Начать с чистого листа: `docker compose down -v`.

Что пока остаётся в браузере (подключат владельцы модулей): лента и отметки, ответы AI, материалы, заявка на доступ. Лента руководителя строится локально из опубликованного на сервере плана. У стажёра и бадди сценарии с сервера пока не загружаются — нужен модуль сообщений.

Устройство:

| Файл | Назначение |
|---|---|
| `src/api.ts` | Общий HTTP-клиент: cookie, `X-CSRF-Token`, `If-Match`, `Idempotency-Key`, ошибки контракта. Свои операции добавляйте в объект `api`. |
| `src/serverScenarios.ts` | Преобразование серверных сценариев (id) в локальное состояние прототипа (имена) и обратно |
| `src/Login.tsx`, `src/login.css` | Экран демо-входа |
| `Dockerfile`, `nginx.conf` | Сборка с `VITE_API=on` и раздача через nginx |
| `tests/serverScenarios.test.ts` | Тесты преобразований и клиента |

## Разработка

Node.js 22.18+ и npm. После распаковки откройте папку `frontend`:

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 4173
npm run check
npm test
npm run build
npm run test:sites
```

Сборка находится в `dist/client`. Её нужно отдавать HTTP-сервером, например `npm run preview`; file:// не поддерживается.

| Файл | Назначение |
|---|---|
| `src/App.tsx` | Лента, наступление дат, настройки, публикация |
| `src/scenarios.ts` | Сценарии, публикация, изоляция историй и миграция локальных данных |
| `src/domain.ts` | Типы, шаблоны, `dueBlocks`, `tasksForRole`, имитации |
| `src/ui.tsx` | Общие компоненты и диалог |
| `src/bot.css` | Компоновка одной переписки |
| `src/origination.css` | Активная типографика, токены и компоненты команды |
| `src/prototype.css` | Токены, формы, конструктор, темы |
| `design/source-audit.md` | Источник Авито и решения Хомыча |
| `design/process-map.md` | Связь 18 BPMN с интерфейсом |
| `design/implementation-handoff.md` | Подключение сервера и данных |
| `design-qa.md` | Проверки и доказательства |
| `design/index.html` | Галерея браузерных снимков |

В архиве `context/` содержит требования, BPMN и уточнение концепции. В репозитории основания находятся в `docs/ai-buddy/` и `output/bpmn-v3/models/`.

Текущий дизайн перенесён из вашей Figma на существующую логику бота. Onest и маскот хранятся локально; основания, токены и адаптации описаны в `design/origination-design-system.md`. Прежнее оформление по публичной статье Авито сохранено только в истории. Иконки интерфейса — Phosphor. GitHub-публикация и новый Figma-файл не создавались.

Проверка нового сценария: выбери роль «Руководитель», открой «Сценарий», создай или открой запись. В панели проверки доступен выбор Саши, Маши и Ильи. Личные вопросы и отметки разделены; одновременно действует один опубликованный вариант на стажёра. Подробности решения: `../docs/ai-buddy/decisions/2026-11-12-scenario-library.md`. QA: `design/scenario-library-qa.md`.

Подсказки вопросов выбираются случайно по текущему этапу опубликованного плана: три вопроса сохраняются до смены этапа. Руководитель не управляет ими. Наборы и определение этапа: `src/suggestions.ts`; выбранные вопросы хранятся отдельно у стажёров в v3. При отсутствии инструкции по отгулу/отпуску бот сообщает об этом и предлагает HR. Решение: `../docs/ai-buddy/decisions/2026-11-12-stage-suggestions.md`.

Проверка подсказок и снимки: `design/stage-suggestions-qa.md`. Всего 37 доменных тестов и 4 проверки сборки/worker.
