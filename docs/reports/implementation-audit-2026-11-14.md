# Аудит реализации Хомыча на 14 ноября 2026

Срез ветки `feat/ai-chat` поверх `main` (`7798742`). Заменяет [аудит на 13 ноября](../archive/implementation-audit-2026-11-13.md), который описывал состояние до модулей сообщений, заявок, ответов, подсказок и материалов.

Основание: [47 функциональных требований 0.4](../product/functional-requirements.md), [OpenAPI](../architecture/openapi.yaml), техническое задание и RAG SDD. «Готово» означает реализацию с автотестами и проверкой в браузере на демо-стенде, а не пилотную приёмку.

## Вывод

Главный продуктовый путь собран целиком: публикация сценария → серверное наступление этапа → адресные сообщения стажёру, бадди и руководителю → вопрос стажёра в основном чате → сохранённый ответ RAG с источниками → материалы руководителя попадают в ответы → заявка на доступ через внешний сервис открывает первую задачу.

- **Публичный API: 23 из 23 операций** контракта реализованы в Go; тест `backend/internal/app/contract_test.go` проверяет маршрут каждой операции по `openapi.yaml`. Ещё 9 операций — расширения для FRONT и демо-стенда, описаны там же с пометками `x-extension` / `x-demo-only`.
- **Требования:** из 47 — 39 реализованы, 5 частично, 3 не реализованы. Нереализованные — три предложения про HR; среди 37 согласованных нет ни одного нереализованного.

## Проверки

| Что | Результат |
|---|---|
| Go, реальная PostgreSQL, `-race` | Все пакеты проходят; покрытие ~89 % |
| Python, реальная PostgreSQL с pgvector | 49 тестов, ruff |
| FRONT | 57 юнит-тестов, проверка типов, сборка |
| Сквозные проверки в браузере (Playwright, Go + Python с детерминированным провайдером) | Вопрос → ответ с источником; ожидание ответа после перезагрузки и при недоступном RAG; материал руководителя → индекс → доступен своей команде и не виден чужой; заявка на доступ; уведомления и сдвиг даты |

Живая модель (Qwen3:4b на CPU) отвечает до минуты на вопрос: интерфейс это учитывает, но для показа лучше GPU или прогрев. Качество ответов на живой модели проверяется вручную; retrieval benchmark — `knowledge/` (`evaluate`).

## Что осталось

1. Экран метрик пользы поверх событий (сколько этапов выполнено, время до доступа, вопросы без ответа) и адаптер Kafka.
2. Фича-флаги (`EVENTS_PUBLISHER` уже управляет публикацией событий).
3. Измерение покрытия FRONT в CI.
4. Решения Авито: SSO и канал доставки (OQ02), сервис доступов (OQ08), правила календаря (OQ04), внутренняя база знаний и роль её владельца.
