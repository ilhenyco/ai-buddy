# Границы системы и роли

**Историческая редакция.** Для новой разработки использовать [../team-specification.md](../team-specification.md) и [../server-handoff.md](../server-handoff.md). Старый OpenAPI сохранён отдельно; текущий контракт — проект 23 операций. OQ01 закрыт, чек-листы не блокируют календарь.


**Историческое сопоставление с BPMN версии 2.** Актуальные модели и таблица связи с 42 требованиями находятся в [BPMN версии 3](../bpmn-v3/README.md). Снимок исходного чек-листа сохранён; поведение после уточнений пользователя определяется требованиями 0.2.

Карта связывает строки 2–41 листа «Чек-лист по ролям» с задачами BPMN. Номер строки соответствует снимку A1:F41. P00 объединяет этапы всего пути и не имеет отдельной строки. P14 используется на трёх карточках MVP, а в исходном листе привязан к строке 12. [Исходный чек-лист](https://docs.google.com/spreadsheets/d/1NWVMqilKgqZi8yAycCZPl8OPpLT64qWxFunl_TIbkYc/edit#gid=1846725631)

**MVP** означает, что приложение реализует указанный шаг. **MVP и ручной шаг** означает, что в приложении виден согласованный вход или есть справка, а работу выполняет человек. **Полная версия** обозначает будущую функцию продукта. **Ручной шаг** выполняется вне приложения. Запуск MVP требует готового опубликованного плана, назначенного бадди и согласованной постановки первой задачи.

| Строка и материал | Роль по чек-листу | Узлы BPMN | Область | Результат и участие AI-buddy |
|---|---|---|---|---|
| 2. Дата выхода и контакты | HR | `P01_date` | Полная версия | HR передаёт подтверждённую дату и контакты для черновика плана. AI не участвует. |
| 3. Назначение бадди и выбор шаблона | Руководитель | `P01_owner` | Полная версия | Руководитель назначает бадди и выбирает шаблон на 6 или 9 месяцев. Приложение сохраняет выбор. AI не участвует. |
| 4. Материалы команды | Бадди | `P01_pack` | Полная версия | Бадди передаёт карточку команды, инструкции и список доступов. AI по запросу отмечает пропущенные поля. |
| 5. Черновик плана | AI-buddy | `P01_draft` | Полная версия | AI предлагает этапы и контрольные точки по выбранному шаблону. Руководитель получает редактируемый черновик и проверяет предложения. |
| 6. Публикация плана | Руководитель | `P01_publish` | Полная версия | AI помогает показать будущий вид плана. Только руководитель публикует согласованную версию. Опубликованный план служит входом в P02. |
| 7. Приглашение к старту | HR | `P01_invite` | Ручной шаг | HR отправляет приглашение и инструкции после публикации. В демо этот шаг уже выполнен. AI не участвует. |
| 8. Первый вход | Стажёр | `P02_login` | MVP | Стажёр входит в демо. Сервер проверяет сессию и опубликованный план. При отсутствии плана экран показывает контакт руководителя, если он известен. |
| 9. Карточка «Мой старт» | AI-buddy | `P02_home` | MVP | API собирает этап, контакты, прогресс и следующий шаг из плана. Интерфейс показывает «Мой старт». Генерация текста для этого шага не требуется. |
| 10. Знакомство с командой | Бадди | `P03_intro` | MVP и ручной шаг | Бадди знакомит стажёра с людьми и каналами. Приложение показывает карточку, AI по запросу помогает найти канал или контакт. |
| 11. Карточка «Команда» | AI-buddy | `P03_show` | MVP | API отдаёт состав команды, каналы и контакт назначенного бадди. Экран показывает карточку и состояние отметки. |
| 12. Знакомство и вопросы | Стажёр | `P03_mark`, `P14_ask` | MVP | Стажёр отмечает знакомство. API сохраняет прогресс. AI по запросу отвечает о команде из разрешённых материалов. |
| 13. Организационные вопросы | HR | `P08_org` | Ручной шаг | HR отвечает на кадровые и организационные вопросы. Отметка о таком разговоре не нужна для трёх карточек MVP. AI не участвует. |
| 14. План адаптации и первая задача | Руководитель | `P07_lead` | MVP и ручной шаг | Руководитель заранее утверждает первую задачу, критерии и нужный ресурс. Демо получает их из опубликованного плана. Приложение проверяет доступ перед показом постановки. |
| 15. Доступы и инструменты | Бадди | `P04_guide`, `P06_no` | MVP и ручной шаг | Бадди объясняет, какой инструмент нужен. Приложение показывает ресурс и состояние. При отказе экран показывает контакт бадди, стажёр связывается с ним сам. |
| 16. Заявка на доступ | Стажёр | `P04_pick`, `P05_confirm`, `P06_read` | MVP | Стажёр выбирает разрешённый ресурс, проверяет черновик, подтверждает отправку и видит статус. Без подтверждения внешнего вызова нет. |
| 17. Черновик и статус заявки | AI-buddy | `P04_suggest`, `P05_call`, `P06_store` | MVP | AI может предложить обоснование. Go API создаёт или находит одну подтверждённую попытку, отправляет её и сохраняет статус. При сбое повтор использует ту же попытку. |
| 18. Подготовка первой задачи | AI-buddy | `P07_block`, `P07_show` | MVP | API проверяет подтверждённое одобрение именно нужного ресурса и рассчитывает состояние карточки. Экран показывает блокер или открывает материалы. |
| 19. Старт первой задачи | Стажёр | `P07_open`, `P07_choose` | MVP | Стажёр открывает постановку и критерии, отмечает «Готов начать». API повторно проверяет доступ и сохраняет отметку. |
| 20. Цели и ожидания | Стажёр | `P08_intern` | Полная версия | Стажёр обсуждает цели с руководителем. AI по запросу оформляет согласованные цели для инструмента прогресса. |
| 21. Командные материалы и разбор задачи | Бадди | `P08_buddy` | MVP и ручной шаг | AI по запросу помогает найти разрешённую инструкцию открытой первой задачи. Бадди разбирает первые результаты вне приложения. |
| 22. Проверка адаптации | Руководитель | `P08_lead` | Полная версия | Руководитель проводит проверку адаптации. Приложение может собрать отмеченный прогресс и известные блокеры к встрече. |
| 23. Учёт прогресса и вводные материалы | HR | `P08_hr` | Полная версия | HR передаёт ссылки на курсы и инструмент прогресса. Приложение показывает материалы нужному стажёру. |
| 24. Защита данных и обучение | Стажёр | `P08_learn` | Полная версия | Стажёр проходит обучение. Приложение показывает назначенные курсы и сроки. Источник отметки о прохождении согласуется для каждого курса. |
| 25. Памятка об учебной практике | HR | `P09_hr` | Ручной шаг | HR сообщает требования и список документов для учебной практики. AI не участвует. |
| 26. План закрытия учебной практики | Стажёр | `P09_agree` | Ручной шаг | Стажёр согласует с HR сроки, документы и действия. AI не участвует. |
| 27. Подготовка экваторной встречи | HR | `P10_hr` | Полная версия | HR согласует дату, формат и шаблон встречи. Приложение показывает утверждённую информацию. |
| 28. Промежуточные результаты | Стажёр | `P10_collect` | Полная версия | Стажёр собирает промежуточные результаты. AI по запросу группирует отмеченные результаты по согласованным целям. |
| 29. Подготовка к экватору | AI-buddy | `P10_show`, `P10_ai` | Полная версия | Приложение показывает материалы экватора. По запросу AI составляет черновик повестки из отмеченного прогресса. |
| 30. Репетиция и следующие задачи | Бадди | `P10_rehearse`, `P10_plan` | Полная версия | Бадди и стажёр репетируют встречу и согласуют следующие задачи. AI по запросу оформляет этот список. |
| 31. Обратная связь и пересмотр плана | Руководитель | `P10_review` | Полная версия | Руководитель обсуждает результаты и утверждает обновлённые цели. Приложение может получить утверждённое изменение плана после встречи. AI не участвует во встрече. |
| 32. Формат финала и сроки решения | Руководитель | `P11_lead` | Полная версия | Руководитель утверждает критерии, формат и срок ответа. Приложение показывает зафиксированную информацию. |
| 33. Организация финала | HR | `P11_hr` | Ручной шаг | HR согласует даты, участников и порядок оформления. AI не участвует. |
| 34. Примеры работ для финала | Бадди | `P11_buddy` | Полная версия | Стажёр и бадди выбирают примеры. AI по запросу помогает составить рассказ на их основе. |
| 35. Чек-лист подготовки к финалу | AI-buddy | `P11_show`, `P11_ai` | Полная версия | Приложение показывает требования, сроки и открытые задачи. По запросу AI готовит черновик выступления. |
| 36. Итоговое выступление и передача задач | Стажёр | `P12_result` | Ручной шаг | Стажёр представляет результаты и передаёт задачи команде. AI не участвует. |
| 37. Передача контекста | Бадди | `P12_handoff` | Ручной шаг | Бадди проверяет ссылки, владельцев и факт приёма задач. AI не участвует. |
| 38. Итоговая оценка и дальнейший шаг | Руководитель | `P12_review`, `P12_yes`, `P12_wait` | Ручной шаг | Руководитель даёт итоговую оценку и сообщает решение либо срок ответа. AI не участвует. |
| 39. Документы, опрос и переход | HR | `P13_hr` | Ручной шаг | HR оформляет документы, проводит опрос и организует переход. AI не участвует. |
| 40. Личный итог и обратная связь | Стажёр | `P13_i` | Ручной шаг | Стажёр заполняет опрос и получает документы через HR. AI не участвует. |
| 41. Завершение плана | AI-buddy | `P13_show`, `P13_wait` | Полная версия | Приложение показывает завершение после отметки ответственного. Если решение ещё ждут, показывает известный срок и контакт. AI использует зафиксированный результат. |

## Что передаётся между этапами

| Переход | Кто подтверждает результат | Какие сведения получает продукт |
|---|---|---|
| P01 → P02 | Руководитель публикует план. HR отправляет приглашение. | Опубликованная версия, стажёр, команда, бадди, контакты, ресурсы и утверждённая первая задача. В MVP данные загружены при подготовке демо. |
| P04 → P05 → P06 | Стажёр подтверждает выбранный ресурс и обоснование. Решение об одобрении принимает сервис доступов. | Черновик → подтверждённая попытка → номер и статус по ID операции. |
| P06 → P07 | Сервис подтверждает доступ к нужному ресурсу. Стажёр отмечает готовность. | Сохранённое одобрение для того же плана и ресурса, затем отметка о готовности. |
| P08 и P09 → P10 | Руководитель обсуждает цели, стажёр собирает результаты, HR ведёт учебную практику. | Для экватора используются подтверждённые цели и отмеченный прогресс. Документы учебной практики обрабатываются через HR. |
| P10 → P11 → P12 | Руководитель утверждает изменения плана и критерии финала. HR организует встречу. | Актуальные цели, сроки, формат и критерии для подготовки финала. |
| P12 → P13 | Руководитель фиксирует оценку и дальнейший шаг. HR координирует оформление. | Статус решения, следующий шаг, срок и контакт при ожидании. Решение и кадровые действия остаются за людьми. |

Технические правила для MVP описаны в [системной спецификации](../system-design.md). Реализация и приёмка разбиты на задачи в [плане передачи](../handoff.md). Для будущих функций перед реализацией отдельно согласуются источники HR-данных, владельцы интеграций и права на кадровые сведения.
