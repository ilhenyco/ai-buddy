# BPMN для разработки AI buddy

**Предыдущая редакция.** После уточнений от 11 ноября 2026 года актуальны [BPMN версии 3](../bpmn-v3/README.md), согласованные с функциональными требованиями 0.2. Эта папка сохранена как история.

Источник процесса — лист 3 [«Чек-лист по ролям»](https://docs.google.com/spreadsheets/d/1NWVMqilKgqZi8yAycCZPl8OPpLT64qWxFunl_TIbkYc/edit#gid=1846725631), A1:F41. Поставка содержит одну обзорную карту и 14 подробных моделей в нотации [BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/).

| ID | Процесс | Область |
|---|---|---|
| P00 | Весь путь стажировки | Обзор |
| P01 | Подготовка до выхода | Полная версия |
| P02 | Первый вход и следующий шаг | Прототип |
| P03 | Знакомство с командой | Прототип и работа бадди |
| P04 | Подготовка заявки на доступ | Прототип |
| P05 | Подтверждение и отправка заявки | Прототип |
| P06 | Проверка статуса доступа | Прототип |
| P07 | Готовность к первой задаче | Прототип и согласованная постановка |
| P08 | Цели адаптации и обучение | Полная версия и справка прототипа |
| P09 | Учебная практика | Ручной процесс HR и стажёра |
| P10 | Экватор стажировки | Полная версия |
| P11 | Подготовка финала | Полная версия |
| P12 | Итог и передача задач | Ручной процесс стажёра, бадди и руководителя |
| P13 | Завершение плана | Полная версия |
| P14 | Ответ по разрешённым источникам | Поддержка трёх сценариев прототипа |

Откройте отдельный файл в редакторе BPMN, например [BPMN Modeler](https://demo.bpmn.io/). Модели содержат координаты, дорожки и свойства элементов. В Word встроены их изображения. Свёртки P00 ссылаются на ID подробных моделей. Модели описывают поведение и помечены как неисполняемые. Переходы рабочего прототипа реализуются в интерфейсе и Go API, их состояние хранится в PostgreSQL.

[Таблица прослеживаемости](../../../output/bpmn-v2/models/traceability.csv) связывает все 40 строк с ID BPMN. В свойствах элементов указаны номер строки, ответственный, результат и роль AI. [Индекс моделей](../../../output/bpmn-v2/models/model-index.json) содержит области, триггеры, результаты, критерии приёмки, узлы и связи. [Системная спецификация](../../archive/system-design.md) описывает данные, права, состояния и контракты. [План передачи](../../archive/handoff.md) связывает актуальные узлы P00–P14 с экранами, API, задачами T1–T5 и проверками.

У заявки три разных операции. Черновик готовится без вызова сервиса. Подтверждение создаёт или находит одну попытку по плану и ресурсу. Проверка статуса читает состояние по ID операции. Ответ модели сам по себе не отправляет заявку и не меняет прогресс. При отказе показывается контакт бадди. При потере ответа повтор использует тот же ID и исходные параметры.

В полной версии человеческие действия остаются на своих дорожках. Источники данных HR, правила публикации плана и отражения итогового решения согласуются перед внедрением. Карта показывает, в каких местах продукт использует их результаты.

Все модели проверены на соответствие XSD OMG, связность входов и выходов, ветки выбора, покрытие строк и повторное открытие после редактирования в BPMN Modeler. Проверки моделей не заменяют автотесты приложения.
